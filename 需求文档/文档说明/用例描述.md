## UC-01 学生注册

| 项 | 内容 |
|---|---|
| 参与者 | 游客 |
| 触发条件 | 用户点击"注册" |
| 前置条件 | 无 |
| 主事件流 | 1. 游客进入注册页；2. 填写学号、密码、确认密码、昵称、联系方式；3. 提交注册表单；4. 系统校验通过，创建账号（密码 BCrypt 加密，角色为学生）；5. 提示"注册成功"并跳转登录页 |
| 备选事件流 | 2a. 学号已被注册 → 提示"该学号已注册"，返回第 2 步；2b. 两次密码不一致 → 提示，返回第 2 步；2c. 学号/联系方式格式不合法 → 提示，返回第 2 步；3a. 必填项为空 → 提示，返回第 2 步 |
| 后置条件 | user 表新增一条学生记录 |
| 对应需求 | FR-01 |

## UC-02 登录/退出

| 项 | 内容 |
|---|---|
| 参与者 | 学生、管理员 |
| 触发条件 | 用户点击"登录" |
| 前置条件 | 已注册且账号未被禁用 |
| 主事件流 | 1. 输入学号、密码并提交；2. 系统校验通过，签发 JWT 令牌；3. 学生进入首页，管理员进入管理后台首页；4. 用户点击"退出"，清除令牌返回登录页 |
| 备选事件流 | 2a. 学号不存在或密码错误 → 提示"学号或密码错误"；2b. 账号被禁用 → 提示"账号已被禁用，请联系管理员" |
| 后置条件 | 客户端保存令牌，后续请求携带令牌 |
| 对应需求 | FR-02、FR-04 |

## UC-03 浏览与检索信息

| 项 | 内容 |
|---|---|
| 参与者 | 游客、学生、管理员 |
| 触发条件 | 进入首页 |
| 前置条件 | 无 |
| 主事件流 | 1. 系统展示已审核通过的物品列表（发布时间倒序，分页）；2. 用户选择分类、类型筛选条件，列表即时刷新；3. 用户输入关键词搜索，系统对标题与描述模糊匹配并展示结果 |
| 备选事件流 | 3a. 无匹配结果 → 显示空状态提示 |
| 后置条件 | 无 |
| 对应需求 | FR-08、FR-09、FR-10 |

## UC-05 发布失物信息

| 项 | 内容 |
|---|---|
| 参与者 | 学生 |
| 触发条件 | 点击"发布信息" |
| 前置条件 | 已登录 |
| 主事件流 | 1. 选择类型（寻物/拾物），填写标题、分类、描述、时间地点、联系方式，上传图片（≤3 张，jpg/png，≤2MB）；2. 提交发布；3. 系统保存信息，审核状态置为"待审核"；4. 提示"发布成功，等待管理员审核"；5. 管理员审核通过后，系统向发布者发送站内消息，信息前台可见 |
| 备选事件流 | 1a. 图片超 3 张/格式非法/超 2MB → 提示并阻止上传；2a. 必填项缺失或超长 → 提示，返回第 1 步；5a. 审核驳回 → 通知发布者驳回理由，信息不展示 |
| 后置条件 | lost_item 表新增记录（审核状态=待审核） |
| 对应需求 | FR-05、FR-07、FR-17 |

## UC-06 编辑/下架信息

| 项 | 内容 |
|---|---|
| 参与者 | 学生、管理员 |
| 触发条件 | 点击"编辑"或"下架" |
| 前置条件 | 已登录；学生仅能操作本人发布的信息，管理员可操作任意信息 |
| 主事件流 | 1. 学生修改信息内容并保存，或点击下架；2. 系统更新信息，或将状态置为"已关闭"；3. 管理员下架违规信息时填写理由并通知发布者 |
| 备选事件流 | 1a. 信息已完成/已关闭 → 不可再编辑；2a. 无权限 → 系统拒绝并提示 |
| 后置条件 | lost_item 表记录更新 |
| 对应需求 | FR-06、FR-15 |

## UC-07 留言

| 项 | 内容 |
|---|---|
| 参与者 | 学生 |
| 触发条件 | 在详情页留言区提交留言 |
| 前置条件 | 已登录 |
| 主事件流 | 1. 输入留言内容并提交；2. 系统保存留言，并向信息发布者发送站内消息提醒；3. 留言展示在详情页 |
| 备选事件流 | 1a. 内容为空 → 提示；2a. 发布者或管理员可删除不当留言 |
| 后置条件 | comment 表新增记录 |
| 对应需求 | FR-16、FR-17 |

## UC-08 发起认领申请

| 项 | 内容 |
|---|---|
| 参与者 | 学生 |
| 触发条件 | 拾物详情页点击"认领" |
| 前置条件 | 已登录；物品状态为"进行中"；申请者非物品发布者；未申请过该物品 |
| 主事件流 | 1. 填写物品细节描述（颜色、品牌、内含物等）；2. 提交申请；3. 系统保存申请（状态=待核验），物品状态置为"处理中"；4. 系统通知物品发布者"有新的认领申请" |
| 备选事件流 | 1a. 描述为空 → 提示；2a. 重复申请 → 提示"您已申请过该物品" |
| 后置条件 | claim 表新增记录，物品状态=处理中 |
| 对应需求 | FR-13 |

## UC-09 信息审核

| 项 | 内容 |
|---|---|
| 参与者 | 管理员 |
| 触发条件 | 进入后台"待审核"列表 |
| 前置条件 | 管理员已登录 |
| 主事件流 | 1. 查看待审核信息详情；2. 点击"通过"，或点击"驳回"并填写理由；3. 系统更新审核状态，向发布者发送审核结果站内消息 |
| 备选事件流 | 无 |
| 后置条件 | lost_item 审核状态更新 |
| 对应需求 | FR-18、FR-17 |

## UC-10 认领核验

| 项 | 内容 |
|---|---|
| 参与者 | 管理员 |
| 触发条件 | 进入后台"认领核验"列表 |
| 前置条件 | 管理员已登录；存在待核验的认领申请 |
| 主事件流 | 1. 查看认领申请与物品详情；2. 判断申请人是否为失主；3. 通过 → 物品状态置为"已归还"，该物品其余认领申请自动拒绝；拒绝 → 填写拒绝理由；4. 系统向申请人发送结果通知 |
| 备选事件流 | 无 |
| 后置条件 | claim 状态与 lost_item 状态更新 |
| 对应需求 | FR-14 |
