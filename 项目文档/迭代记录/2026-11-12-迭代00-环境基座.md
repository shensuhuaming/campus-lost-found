## 1 目标与范围

- **目标**：交付一个"测试同学能一键部署、开发能直接开工"的环境基座。
- 依据：需求规格说明书 V1.0（第 2.3 运行环境、5.2 数据字典、NFR-05 可维护性）。
- 范围：工程骨架、数据库基线、Docker 编排、测试与 CI 基座、需求解读文档。
- **不在本次范围**：注册登录、物品发布、认领、管理后台等全部业务功能（待设计文档）。

## 3 关键设计决策

| 决策 | 备选方案 | 选择理由 | 影响面 |
|---|---|---|---|
| 后端 JDK 17 + Spring Boot 3.5.9 | JDK 21/24、Boot 4.x | 需求书明确 JDK 17；Boot 3.5 是 3.x 最新稳定线，且与团队现有缓存/资料一致 | 编译目标、IDE 配置 |
| 数据库端口映射 3307 | 3306 | 本机已有 MySQL 8.0.46 占用 3306 | 本机开发连接串、README |
| 前端 dev 用 Vite 代理 `/api` | 直接跨域 | 与生产 nginx 同源代理一致，减少环境差异 | 前端配置 |
| 健康检查自检接口 `/api/system/health` | 只用 actuator | 一次返回应用/JDK/数据库状态，测试同学看得懂 | 测试入口 |
| 持久层暂用 `spring-boot-starter-jdbc` | 直接上 MyBatis-Plus / JPA | 选型未定，先只做连通性验证，避免返工 | 后续 DTO/Mapper 结构 |
| compose 显式 `name: clf` | 依赖目录名 | 目录含中文，compose 推导项目名失败 | 容器/网络/卷命名 |

## 6 对测试同学的影响

- 新增接口：仅 `GET /api/system/health`（自检，无业务语义）。
- 首次部署需重置数据库：是（`docker compose --profile full down -v` 后重新 `up`，会重跑 `db/init`）。
- 回归范围：环境自检页两个状态（后端、数据库）均为 UP；`docker compose ps` 三容器 healthy。
- 已知限制：需先启动 Docker Desktop；Docker Hub 直连可能超时（用镜像站拉取后 tag）。

## 7 回滚方法

```bash
# 回到基座版本
git checkout v0.1.0
# 或撤销某次提交
git revert <commit>
# 彻底重置本地环境（丢数据）
docker compose --profile full down -v && docker compose --profile full up -d --build
```
