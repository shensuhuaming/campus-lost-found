# 项目交接说明

> 面向：接手本项目的开发同学、**后续负责集成测试的同学**。
> 目标：不依赖原开发者，30 分钟内能独立跑起来、跑通测试、知道去哪改代码。
> 对应版本：`v1.0.0`（M1~M6 完成，138 个单元测试）。

## 1 30 分钟上手（照着做即可）

### 1.1 前置环境

| 工具 | 版本 | 检查命令 |
|---|---|---|
| Docker Desktop | 4.x（需先手动启动） | `docker version` |
| JDK | 17 | `java -version` |
| Maven | 3.9+ | `mvn -v` |
| Node.js | 20+（推荐 22） | `node -v` |
| Git | 任意较新版 | `git --version` |

> 只用 Docker 跑系统的话，JDK/Maven/Node 可以不装；要改代码或跑单测才需要。

### 1.2 启动全栈（约 3~5 分钟，首次构建更久）

```bash
git clone https://github.com/shensuhuaming/campus-lost-found.git
cd campus-lost-found

# 1) 准备环境变量（.env 已被 .gitignore 忽略，不会提交）
cp .env.example .env        # Windows: copy .env.example .env

# 2) 关键：数据库名必须是 lost_found（与 DDL 一致），检查 .env 中这一行
#    MYSQL_DATABASE=lost_found

# 3) 启动
docker compose --profile full up -d --build

# 4) 看状态，backend 应为 healthy
docker compose --profile full ps
```

### 1.3 验收启动结果（三件事都要过）

```bash
# ① 健康检查：服务 + 数据库
curl http://localhost:8080/api/system/health

# ② 前端首页
#    浏览器打开 http://localhost/ 和 http://localhost/admin

# ③ 端到端冒烟（19 步，全部 PASS 才算环境 OK）
scripts\smoke-test.cmd
```

演示账号：管理员 `admin / Admin@123`；学生 `2022304599 / pass1234`（详见 [使用说明书 §1.3](使用说明书.md)）。

### 1.4 本地开发模式（改代码时）

```bash
# 后端：IDE 里跑 CampusLostFoundApplication（profile=local），或
cd backend && mvn spring-boot:run

# 前端：Vite 开发服务器，/api 自动代理到 8080
cd frontend && npm install && npm run dev     # http://localhost:5173
```

> 后端连容器里的 MySQL 即可（`localhost:3307`，库 `lost_found`），无需在本机装 MySQL。

**修改前必看（踩过坑的地方）**

| 文件 | 作用 | 改动注意 |
|---|---|---|
| `common/ResultCode.java` | 错误码唯一来源（含 HTTP 映射） | 新增码要同步《API 接口规格》与前端提示文案 |
| `security/JwtInterceptor.java` | 白名单 + 禁用即时校验 | 改白名单要同步安全测试；`/api/items` 等公开读接口是有意放行的 |
| `util/ItemStatusMachine.java` | 物品/认领状态迁移的唯一入口 | 改流转必须同步单测、详细设计 4.4 与使用说明书状态表 |
| `service/impl/MessageServiceImpl.java` | 站内消息，**事务提交后**推送（afterCommit） | 不要改成"直接插入"，否则业务回滚会留下幽灵通知 |
| `init/DataInitializer.java` | 首次启动创建管理员 | `ADMIN_INIT_PASSWORD` 只在账号不存在时生效 |
| `db/init/01-schema.sql` | 表结构 | 改表要同步实体、`lost_found.sql`、测试数据 |
| `frontend/src/api/http.ts` | axios 拦截器（带 token、401 清登录态跳转） | 改 401 行为要同步路由守卫与页面提示 |
| `frontend/vite.config.ts` | ECharts 单独分包 | 新增图表库时注意别把主包撑大 |

## 3 改一个需求的完整路径（以"认领增加撤销"为例）

1. **先看文档**：《API 接口规格》5.x、《详细设计》4.4、`项目文档/迭代记录/` 最近一篇；
2. **建分支**：`feature/claim-cancel`（规范见 `CONTRIBUTING.md`）；
3. **后端**：DTO → Service 接口 → Impl（状态机 + 条件更新）→ Controller → **补单元测试**；
4. **前端**：`src/api/claim.ts` → 页面按钮与交互 → 类型检查通过；
5. **文档**：更新 `CHANGELOG.md`、新增 `项目文档/迭代记录/` 一篇（目标/变更/验证/遗留/回滚）；
6. **自测**：`mvn test`（backend）+ `npm run build`（frontend）+ 冒烟脚本；
7. **PR**：填 `.github/PULL_REQUEST_TEMPLATE.md`，CI 必须绿；
8. **合并**：`git merge --no-ff`，打 tag（如 `v1.1.0`），push（含 tag）。

### 5.2 第一次跑冒烟：怎么读结果

```powershell
scripts\smoke-test.cmd
# 亦可显式绕过执行策略：
# powershell -NoProfile -ExecutionPolicy Bypass -File scripts\smoke-test.ps1
```

输出形如：

```
  [PASS] 7. 管理员审核通过后前台可见
  [FAIL] 12. 管理员核验列表可见该申请
         断言失败：待核验列表中应有该申请（期望 [1]，实际 [0]）
=== 结果：通过 18 / 失败 1 ===
```

- 脚本每次用**随机学号**注册两个新用户，不污染既有数据，可反复跑；
- 失败时按顺序排查：先看 `docker compose logs -f backend` 的异常栈，再对照 [使用说明书 §6 错误码](使用说明书.md)；
- 想手工复现某一步：脚本里每一步都写了接口路径与请求体，直接复制到 Postman/curl 即可。

### 5.3 测试数据策略

| 场景 | 做法 |
|---|---|
| 冒烟/快速回归 | 直接跑 `scripts\smoke-test.cmd`，自动造数据 |

### 5.4 缺陷提交规范（缺一不可）

```text
标题：[模块] 一句话现象（如：[认领] 核验通过后物品状态未变为已完成）
环境：本机 Docker / v1.0.0 / commit 短 SHA
角色：游客 / 学生A（发布者）/ 学生B（认领人）/ 管理员
前置数据：物品 id、认领 id、账号学号
复现步骤：1. … 2. … 3. …
期望：…（引用需求条目，如 FR-14）
实际：…（附错误码，如 code=2003）
证据：截图 / 接口原始响应 / `docker compose logs backend` 相关片段
影响：阻塞 / 严重 / 一般 / 建议
```

> 有错误码的缺陷优先看 `ResultCode` 与《API 接口规格》1.4，能快速判断是"实现错"还是"用例预期错"。

### 5.5 这些是设计如此，不是缺陷（避免误报）

| 现象 | 原因 |
|---|---|
| 新发布的信息首页看不到 | 需管理员审核通过（FR-18） |
| 编辑信息后又变成"待审核" | 防止绕过审核改内容（评审 P0 决定） |
| 首页列表能看到"已完成"的信息 | 列表条件为 `已过审 且 未关闭`（对齐 API 4.1，评审已确认） |
| 详情页联系方式是 `137****2222` | 游客/非发布者脱敏；发布者与管理员可见完整 |
| 认领被拒后同一物品无法再次申请 | 数据库唯一约束 `uk_claim_item_applicant`（API 5.1 规则 4），需联系管理员或关注其他信息 |
| 认领按钮灰掉显示"已申请" | 已提交过申请 |
| 管理员关闭信息必须填理由 | 审计要求（评审 P0-3） |
| 消息红点最多显示 99+，60 秒才刷新 | 详细设计 4.5.4 轮询策略 |
| 图片最多 3 张、单张 ≤2MB、仅 jpg/png | FR-07；上传做了文件头魔数校验 |
| 统计"信息总数"包含待审核与已关闭 | 指标口径见 API 7.9 |

### 5.6 回归范围建议（改了什么，就多测什么）

| 改动区域 | 必跑自动化 | 建议手工回归 |
|---|---|---|
| 认证 / 拦截器 / 权限 | `JwtInterceptorTest`、`AuthServiceImplTest`、冒烟 1~5 | 登录、退出、未登录跳转、管理员入口拦截、禁用账号登录 |
| 物品发布 / 编辑 / 关闭 / 状态 | `ItemServiceImplTest`、冒烟 6~8、14 | 发布 3 图、编辑后重审、关闭后前台不可见 |
| 认领 / 核验 | `ClaimServiceImplTest`、冒烟 9~13 | 重复申请、认领自己、核验通过后其余申请自动拒绝 |
| 留言 / 消息 | `CommentServiceImplTest`、`MessageServiceImplTest`、冒烟 15~16 | 自己给自己留言无通知、已读后角标减少 |
| 管理后台 | `AdminServiceImplTest`、冒烟 7、17~18 | 驳回必填理由、分类重名/引用删除、禁用用户 |
| 前端公共层（http.ts / 路由 / 布局） | 前端构建 + 全量冒烟 | 登录态过期（401）跳转、直接访问受保护路由 |

### 5.7 环境类常见问题（排错表）

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker compose` 报 "project name must not be empty" | 仓库路径含中文 | 已在 compose 里写死 `name: clf`，不要删 |
| 容器起来了但首页显示后端"不可用" | `.env` 里 `MYSQL_DATABASE` 不是 `lost_found` | 改名后 `docker compose --profile full up -d --build` |
| 拉镜像超时 | Docker Hub 网络 | 用镜像加速器，或先 `docker pull docker.m.daocloud.io/...` 再 `docker tag` |
| 后端测试报 Maven 本地仓库无权限 | 本机 `.mvn` 指向只读目录 | 加 `-Dmaven.repo.local=%USERPROFILE%\.m2\repository` |
| 前端 `npm run build` 报 esbuild `Access is denied` | 中文路径 + 临时目录权限 | 设置 `TEMP`/`TMP` 到项目内 `.tmp` 目录 |
| PowerShell 跑冒烟脚本报"字符串缺少终止符" | 脚本是 UTF-8 **无 BOM**，5.1 按 ANSI 解析 | 用 VS Code "UTF-8 with BOM" 另存；仓库内脚本已带 BOM |
| 端口 80/8080 被占用 | 本机已有服务 | 改 `.env` 的 `FRONTEND_PORT` / `BACKEND_PORT` |
| 上传的图片 404 | 卷 `clf-uploads` 未挂载或 nginx 未反代 | 检查 `docker-compose.yml` 与 `frontend/nginx.conf` |

## 6 Git 与账号交接

1. **仓库权限**：GitHub 仓库 `shensuhuaming/campus-lost-found`（public）。需要写权限的组员由 owner 在 *Settings → Collaborators* 邀请；只读测试可直接 clone。
2. **分支保护**：`main` 只接受 PR（建议开启 required checks = CI）。
3. **版本标签**：每完成一个里程碑打 tag（现有 `v0.1.0`、`v1.0.0`），`git push --follow-tags` 一并推送。
4. **敏感信息**：`.env` 已在 `.gitignore` 中；`JWT_SECRET`、`ADMIN_INIT_PASSWORD`、数据库口令只放本地 `.env` 或部署平台的环境变量，**不要提交**。共享 PAT 不要写进仓库或文档。
5. **演示环境重置**：见 §5.3；生产/演示前务必改 `ADMIN_INIT_PASSWORD` 与 `JWT_SECRET`。
