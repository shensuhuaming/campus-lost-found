## 1 开发任务

**目标**：让"想问一句"和"有事通知我"可用——详情页可留言、发布者收到提醒；所有审核/认领事件的结果在消息中心可见。

**范围**

- 是：发表留言（通知发布者）、删除留言（本人/管理员）、消息列表（只看自己、可筛选）、标记已读（幂等）、未读数。
- 不是：消息删除、全部已读、留言回复（楼中楼）、留言分页（详情只取前 10 条）。

**依赖**：`comment`、`message` 表；`MessageService`（afterCommit 推送）；`ItemDetailVO`（留言读取）。

**完成标准**

1. 留言落库并通知发布者（自己留言不通知）；
2. 删除留言权限正确（本人/管理员，否则 2002）；
3. 消息只能看/改自己的（越权 2002），已读幂等，未读数正确；
4. 发送人为系统时昵称显示"系统"；
5. 单测覆盖推送/权限/幂等/空列表。

## 2 设计要点

### 2.1 消息推送（评审 P0-6）

```text
业务事务内调用 messageService.push(...)
  ├─ 有事务同步 → 注册 afterCommit 回调（提交成功才 insert）
  └─ 无事务     → 立即 insert
失败只记日志，不影响主业务
```

这样避免"核验失败但用户收到成功通知"的幽灵消息。

### 2.2 消息类型

| type | 文案 | 触发 |
|---|---|---|
| 1 | 审核结果 | M6 审核通过/驳回 |
| 2 | 留言提醒 | 本模块留言（携带留言人 `from_user_id`） |
| 3 | 认领申请提醒 | M4 发起认领 |
| 4 | 认领结果 | M4 核验通过/拒绝、他人抢先、信息关闭自动取消 |
| 5 | 系统通知 | 寻物推进、关闭等 |

### 2.3 关键规则

| 规则 | 说明 |
|---|---|
| 留言可见性 | 物品须存在且已过审，否则 2004；内容 1~200 字 |
| 留言通知 | 内容含留言人昵称 + 物品标题 + 前 30 字摘要；自己给自己留言不推送 |
| 消息查询 | `to_user_id = 当前用户`；`from_user_id=0` 显示"系统"；时间倒序 |
| 已读 | 不存在 2004、非本人 2002、已读重复调用直接返回成功（幂等） |
| 未读数轮询 | 前端 60 秒一次（详细设计 4.5.4），路由切换也刷新 |

### 2.4 数据表

- `comment(id, item_id, user_id, content, created_at)`
- `message(id, to_user_id, from_user_id, type, content, item_id, is_read, created_at)`
