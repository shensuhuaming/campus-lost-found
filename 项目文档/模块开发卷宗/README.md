# 模块开发卷宗 · 索引与编制说明

> 对应标准：GB/T 8567《计算机软件文档编制规范》中的「模块开发卷宗」。
> 用途：以**模块**为单位，留痕"这个模块是谁开发的、按什么设计做的、代码在哪、怎么测的、测出了什么"。
> 版本：v1.0.0　编制日期：2026-11-19

---

## 1 模块开发卷宗是什么

模块开发卷宗不是一份文档，而是**每个模块一套的开发过程记录**。本项目的每份卷宗固定包含 8 节：

| 节 | 内容 | 回答什么问题 |
|---|---|---|
| 1 模块标识 | 编号、名称、对应需求与设计章节、负责人、版本 | 这个模块是谁的、依据哪份设计 |
| 2 开发任务 | 目标、范围、依赖、完成标准 | 当初答应做什么、做到什么程度算完 |
| 3 设计要点 | 关键类、状态机/业务规则、数据表、接口 | 为什么这样实现 |
| 4 程序清单 | 后端/前端文件与实际行数 | 代码到底在哪 |
| 5 接口清单 | 方法、路径、权限、成功/失败码 | 对外契约是什么 |
| 6 单元测试记录 | 测试类、用例数、覆盖点、执行命令与结果 | 怎么证明它对 |
| 7 验证与证据 | 迭代记录、截图、冒烟步骤、手工结论 | 除了单测还验了什么 |
| 8 遗留与风险 | 已知缺口、设计取舍 | 还剩什么没做 |

## 3 与其他文档的分工（避免重复维护）

| 文档 | 粒度 | 面向 | 不做什么 |
|---|---|---|---|
| **模块开发卷宗**（本目录） | 模块 | 评审、答辩、交接 | 不写每日流水 |
| [程序开发记录](../程序开发记录.md) | 天/迭代 | 过程追溯、问题复盘 | 不贴大段代码 |
| [迭代记录](../迭代记录/) | 迭代 | 变更清单、验证证据、回滚 | 不按模块拆分 |
| [CHANGELOG](../CHANGELOG.md) | 版本 | 使用者关注的接口与行为变化 | 不写实现细节 |
| [详细设计](../../项目设计/详细设计/详细设计说明书.md) | 设计 | 设计组产出，权威依据 | 不记录实现偏差 |

> 一致性原则：卷宗里的接口、错误码、状态必须与《API 接口详细规格》《详细设计》一致；若实现与设计有偏差，在卷宗 §8 明确写出并说明理由（本项目有两处已批准的偏差，见 M3、M6 卷宗）。

## 4 编制与维护方式

1. **先有任务后有卷宗**：每个模块开工前写 §1、§2；实现过程中补 §3~§5；提测前补 §6~§7；
2. **测试结果必须可复现**：写命令 + 期望输出（本项目统一用 `mvn -B test` 与 `scripts\smoke-test.cmd`）；
3. **遗留不隐藏**：§8 如实记录未做项与原因，交接时逐条确认；
4. **改动后同步**：接口或规则变化，当天更新卷宗对应小节，并在 `程序开发记录.md` 记一条。
