## 1 开发任务

**目标**：让游客无需登录即可找到信息——按分类/类型筛选、按关键词搜索、查看详情（联系方式脱敏）。

**范围**

- 是：`GET /api/items`（筛选、搜索、排序、分页）、`GET /api/items/{id}`、`GET /api/categories`。
- 不是：发布/编辑（M2）、认领（M4）、留言（M5）。

**完成标准**

1. 只展示已过审且未关闭的信息；
2. 关键词搜索标题命中优先，其次按时间倒序；
3. 详情返回图片、发布者、留言前 10 条、我的认领状态，联系方式按登录态脱敏；
4. 未过审信息对非本人/非管理员返回 2004；
5. 列表页无 N+1（分类名与封面批量补齐）。

## 2 设计要点

### 2.1 可见性口径（已批准的设计偏差）

| 位置 | 口径 | 依据 |
|---|---|---|
| 列表 | `audit_status=1 AND item_status <> 3`（**包含已完成**） | 《API 规格》4.1 固定条件；评审确认"已完成信息保留展示，便于追溯" |
| 待审队列 | `audit_status=0 AND item_status <> 3` | 已关闭信息不进待审 |
| 详情 | `audit_status<>1` 时仅发布者/管理员可见，否则 2004 | 《详细设计》4.3.3 |

> 偏差说明：详细设计 4.3.1 原文写"仅进行中/处理中"，实现按 API 规格 4.1 的"`item_status<>3`"执行，已在本卷宗与迭代记录 07 中登记，属**已批准偏差**。

### 2.2 搜索实现

```sql
SELECT * FROM lost_item
WHERE audit_status = 1 AND item_status IN (0, 1)
  [AND type = ?] [AND category_id = ?]
  AND (title LIKE ? OR description LIKE ?)
ORDER BY (CASE WHEN title LIKE ? THEN 0 ELSE 1 END) ASC, created_at DESC
```

- 关键词中的 `%`、`_`、`\` 先转义，避免通配符导致全表扫描；
- 分页交给 MyBatis-Plus `PaginationInnerInterceptor`；
- 注意：搜索分支固定 `IN (0,1)`（只搜"可认领中"的信息），与列表分支的 `<>3` 略有差异，属设计取舍，已登记。

### 2.3 详情组装

1. 基本信息 + 分类名 + 发布者（学号脱敏 `2022****00`）；
2. 图片按 `sort` 升序；
3. 留言按时间正序取前 10 条并批量补昵称；
4. `contact`：发布者/管理员见明文，其他人见 `137****2222`；
5. `myClaimStatus`：未登录为 `null`，登录后查该用户对该物品的最新申请状态。

## 7 遗留与风险

| 项 | 说明 | 影响 | 计划 |
|---|---|---|---|
| 搜索分支固定 `IN (0,1)` | 搜索时看不到"已完成"，与列表口径不同 | 低（可解释为"只搜可认领中的"） | 建议与需求确认后统一 |
| 无搜索历史/热词 | 设计未要求 | 无 | 二期 |
| 列表无排序选项（最新/最热） | `sort` 参数预留但仅实现 time/relevance | 低 | 按需 |
| 详情只返回前 10 条留言 | 与设计一致，无"查看更多" | 低 | 二期分页 |
