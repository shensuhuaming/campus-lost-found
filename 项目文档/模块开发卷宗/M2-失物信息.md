## 1 开发任务

**目标**：让用户能把"我丢了/我捡到了"变成一条带图、可被检索的信息，并在归还后正确收口（关闭或标记完成）。

**范围**

- 是：发布（≤3 图）、图片上传校验、编辑、关闭、寻物 0→1→2 推进、越权与状态校验。
- 不是：审核（M6）、认领（M4）、留言（M5）。

**依赖**：`lost_item`、`item_image` 表；本地/卷 uploads 目录；`ItemStatusMachine`；`MessageService`（关闭时通知）。

**完成标准**

1. 发布后为待审核、进行中，归属当前用户；
2. 图片三重校验（白名单正则、文件存在、未被其他信息引用）+ 上传侧类型/大小/文件头校验；
3. 同一状态的非法迁移一律 2003，且不产生部分写入；
4. 编辑后回到待审核；关闭后前台不可见；管理员关闭必须填理由；
5. 单元测试覆盖各类非法输入与并发条件更新。

## 2 设计要点

### 2.1 状态机（`util/ItemStatusMachine`）

```
进行中(0) ──→ 处理中(1) ──→ 已完成(2)
   │              │
   └──→ 已关闭(3) ←┘        已完成/已关闭为终态
```

- 0→1、0→3；1→0（核验拒绝回退）、1→2、1→3；
- `checkClose(from)` 要求 from ∈ {0,1}；非法统一抛 `ITEM_STATUS_ILLEGAL(2003)`。

### 2.2 关键规则

| 规则 | 说明 |
|---|---|
| 发布即待审核 | `audit_status=0`，前台不可见，发布者可在个人中心看到 |
| 图片校验（评审 P0-5） | 正则 `^/uploads/\d{6}/[0-9a-f]{32}\.(jpg\|jpeg\|png)$` + 文件存在 + `item_image` 未被其他信息引用；最多 3 张（4004） |
| 上传校验 | 空 4001、>2MB 4002、扩展名+jpg/png 文件头魔数不匹配 4003；UUID 重命名，按 `yyyyMM` 分目录 |
| 编辑限制 | 仅"进行中"可编辑；编辑后 `audit_status=0`、清空 `reject_reason`（防绕过审核） |
| 关闭 | 0/1 可关闭；管理员必填 1~100 字理由写 `close_reason`；关闭时把待核验认领自动拒绝并通知 |
| 并发 | 关闭/推进使用条件更新（`WHERE item_status=原值`），影响行数 ≠1 视为冲突返回 2003 |
| 时间校验 | 发生时间不得晚于当前时间 +1 天，否则 1001；Jackson 统一 `yyyy-MM-dd HH:mm:ss` |

### 2.3 数据表

- `lost_item(id, user_id, type, title, description, category_id, happen_time, happen_place, contact, audit_status, item_status, reject_reason, close_reason, created_at, updated_at)`
- `item_image(id, item_id, url, sort, created_at)`；`sort=0` 为封面。

## 7 遗留与风险

| 项 | 说明 | 影响 | 计划 |
|---|---|---|---|
| 点击"编辑"后可改类型（寻物↔拾物） | 设计未禁止，可能造成认领语义混乱 | 低 | 建议限制类型不可改，待需求确认 |
| 上传接口未限制单用户当日张数 | 只能靠发布侧 ≤3 张兜底 | 低 | 二期可加记录表 |
| 图片无删除清理机制 | 编辑替换后旧图成为孤儿文件（数据库记录已删，磁盘文件仍在） | 低（磁盘增长） | 二期可加清理任务 |
| 关闭为终态，不可恢复 | 与设计一致 | 无 | — |
