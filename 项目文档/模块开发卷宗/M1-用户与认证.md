## 1 开发任务

**目标**：建立"谁在用系统"的基础能力——学生可注册登录、维护个人资料与密码、查看自己的发布/认领/留言；系统能识别身份与角色，并对禁用账号即时拦截。

**范围**

- 是：注册、登录、退出、JWT 鉴权、拦截器、个人资料、修改密码、我的三个列表、管理员初始化、账号禁用（接口在 M6）。
- 不是：密码找回、第三方登录、头像上传、消息通知（M5）。

**依赖**：MySQL `user` 表；公共基座（`Result`/`ResultCode`/异常处理/分页）；容器环境。

**完成标准**

1. 注册/登录/退出接口按《API 规格》返回，错误码正确；
2. 未登录访问受保护接口返回 2001，越权返回 2002，禁用账号 1004；
3. 个人资料与改密可用，改密后强制重新登录；
4. 我的三个列表分页结构统一、无 N+1；
5. 单元测试覆盖正常/边界/异常分支。

## 2 设计要点

### 2.1 身份与鉴权

| 机制 | 实现 | 说明 |
|---|---|---|
| 密码存储 | BCrypt（cost=10，`PasswordConfig`） | 不存明文；注册时 `passwordEncoder.encode` |
| 令牌 | JWT HS256，12 小时（`JwtUtil`，密钥 ≥32 字节否则启动失败） | 载荷 `uid`+`role`，无刷新令牌 |
| 拦截 | `JwtInterceptor` 注册在 `/api/**` | 公开读接口白名单：`GET /api/items`、`/api/items/**`、`/api/categories`、`/api/system/**`、`/uploads/**`；公开写：`POST /api/auth/login`、`/api/auth/register` |
| 禁用即时生效 | 拦截器每次请求查库校验 `user.status` | 禁用后旧 token 下一次请求即被拒（返回 1004） |
| 当前用户 | `SecurityUtil`（ThreadLocal） | `getUserId()`、`isAdmin()`、`requireAdmin()`；请求结束清理 |

### 2.2 关键规则

1. 学号：6~12 位数字且唯一；昵称 2~12 字不含空白；手机号 11 位；密码 6~20 位且含字母与数字；
2. 登录失败统一 1003（不区分"学号不存在"与"密码错"，避免账号枚举）；
3. 个人中心统计：`published`、`claiming`、`claimingPending`、`comments`（与本模块列表口径一致，待核验=认领状态 0）；
4. 我的三个列表：批量补齐分类名/封面/认领数/物品标题，避免 N+1；
5. 管理员账号由 `DataInitializer` 启动时幂等创建（口令来自 `ADMIN_INIT_PASSWORD`）。

### 2.3 数据表

`user(id, student_no, nickname, phone, password, role, status, created_at, updated_at)`；唯一索引 `uk_user_student_no`。

## 7 遗留与风险

| 项 | 说明 | 影响 | 计划 |
|---|---|---|---|
| 无密码找回 | 需管理员协助 | 低（演示环境） | 二期 |
| JWT 无法主动吊销 | 改密后旧 token 在有效期内仍可用（前端已强制登出） | 低~中 | 二期可加 token 版本号/黑名单 |
| 登录无失败次数限制 | 可被暴力尝试 | 中 | 演示环境可接受，生产需加限流 |
| `DashboardView.vue` 已不再被路由引用 | 早期环境自检页，功能已被首页取代 | 无 | 可删除（保留不影响构建） |
